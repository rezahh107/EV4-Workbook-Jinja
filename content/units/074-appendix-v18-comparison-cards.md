<h2>1. 🆚 Variable در برابر Global Class</h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p>Variable مثل مادهٔ خام است: آرد، شکر، رنگ یا پیچ. Global Class مثل دستور پخت کامل است: یک ترکیب آماده که چند ماده و چند قانون را با هم استفاده می‌کند.</p></section>
<section><h3>۲. تعریف دقیق</h3><p>Variable در Elementor 4 یک مقدار قابل مدیریت است؛ مثل رنگ، فونت یا اندازه. Global Class یک مجموعه Style است که می‌تواند چند property را با هم روی چند Element اعمال کند.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>اگر هر مقدار را مستقیم روی هر Element بنویسی، بعداً تغییر برند، فاصله‌ها یا فرم دکمه‌ها تبدیل به شکار خطا می‌شود. Variable منبع حقیقت مقدار است؛ Global Class منبع حقیقت ظاهر تکرارشونده است.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p><code dir="ltr">color-brand = #0066cc</code> یک Variable است. <code dir="ltr">btn-primary</code> یک Global Class است که ممکن است background را از <code dir="ltr">color-brand</code> بگیرد، color را white بگذارد، padding بدهد و radius را از <code dir="ltr">radius-button</code> بخواند.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>اشتباه رایج این است که فقط Variable بسازی و بعد همان Variableها را دستی روی ۲۰ دکمه اعمال کنی. این هنوز یک سیستم کامل نیست؛ فقط مقدارها را تمیز کرده‌ای.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>Variable مقدار را نگه می‌دارد؛ Global Class تصمیم طراحی را.</li><li>مقدار تکراری را Variable کن؛ ظاهر تکراری را Global Class کن.</li><li>بهترین سیستم: Variable داخل Global Class استفاده می‌شود.</li></ul></section>
</div>

<section class="comparison-card semantic-complete" id="compare-local-global-class">
<h2>2. 🆚 Local Class در برابر Global Class</h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p>Local Class مثل لباس دوخته‌شده برای یک نفر است. Global Class مثل یونیفرمی است که چند نفر می‌پوشند.</p></section>
<section><h3>۲. تعریف دقیق</h3><p>Local Class مخصوص همان Element است. Global Class قابل reuse در چند Element است و در Class Manager مدیریت می‌شود.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>V4 کلاس‌محور است؛ اگر ندانی یک Style محلی است یا عمومی، صفحه‌ات پر از تصمیم‌های تکراری و غیرقابل نگهداری می‌شود.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p>اگر فقط یک Hero Heading خاص باید اندازهٔ متفاوت داشته باشد، Local Class کافی است. اگر همهٔ Headingهای سکشن باید یک ظاهر مشترک داشته باشند، Global Class مثل <code dir="ltr">section-title</code> بساز.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>هر چیزی را Global کردن هم بد است. اگر یک استثنای واقعی است، Global Class نساز؛ چون بعداً معنی کلاس گم می‌شود.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>Local یعنی همین Element.</li><li>Global یعنی قابل استفاده در چند جا.</li><li>استثنا را Local نگه دار؛ الگو را Global کن.</li></ul></section>
</div>

<section class="comparison-card semantic-complete" id="compare-global-class-component">
<h2>3. 🆚 Global Class در برابر Component</h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p>Global Class لباس است؛ Component خودِ قطعهٔ آماده است. کلاس فقط ظاهر می‌دهد، Component ساختار را هم با خودش می‌آورد.</p></section>
<section><h3>۲. تعریف دقیق</h3><p>Global Class مجموعه‌ای از Styleهاست. Component یک ساختار Global Class با Master و Instance است که می‌تواند چند Element، محتوا و استایل را کنار هم نگه دارد.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>اگر کارت محصول را فقط با Class بسازی، هنوز باید تصویر، عنوان، قیمت و دکمه را هر بار بچینی. Component وقتی لازم است که ساختار تکرار می‌شود، نه فقط ظاهر.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p><code dir="ltr">card-base</code> ظاهر کارت را می‌دهد. اما <code dir="ltr">Product Card Component</code> شامل Image، Heading، Price و Button است.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>Component را به‌جای Class استفاده نکن. برای یک دکمه ساده، Global Class کافی است؛ برای کارت کامل، Component منطقی‌تر است.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>Style تکراری = Global Class.</li><li>Structure تکراری = Component.</li><li>Component کلاس قوی‌تر نیست؛ قطعهٔ ساختاری زنده است.</li></ul></section>
</div>

<section class="comparison-card semantic-complete" id="compare-state-interaction">
<h2>4. 🆚 State در برابر Interaction</h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p>State قیافهٔ عنصر در یک وضعیت است؛ Interaction رفتار عنصر وقتی اتفاقی می‌افتد. یکی عکس است، یکی فیلم.</p></section>
<section><h3>۲. تعریف دقیق</h3><p>State مثل Hover، Focus یا Active تعیین می‌کند Element در آن وضعیت چه شکلی باشد. Interaction با Triggerهایی مثل page load، scroll، hover یا click رفتار/حرکت ایجاد می‌کند.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>خیلی‌ها Hover State را با Hover Interaction قاطی می‌کنند. نتیجه‌اش صفحه‌ای است که هم از نظر CSS شلوغ است، هم رفتارهایش غیرقابل پیش‌بینی می‌شود.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p>Hover State رنگ دکمه را عوض می‌کند. Hover Interaction می‌تواند دکمه را scale کند یا یک عنصر دیگر را حرکت بدهد.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>برای یک تغییر رنگ ساده Interaction نساز. برای حرکت سناریومحور یا scroll-based فقط State کافی نیست.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>State می‌پرسد: در این وضعیت چه شکلی باشم؟</li><li>Interaction می‌پرسد: وقتی این اتفاق افتاد چه رفتاری کنم؟</li><li>ظاهر ساده را با State حل کن؛ رفتار را با Interaction.</li></ul></section>
</div>

<section class="comparison-card semantic-complete" id="compare-padding-margin-gap">
<h2>5. 🆚 Padding در برابر Margin در برابر Gap</h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p>Padding فضای داخل جعبه است، Margin فاصلهٔ بیرون جعبه، Gap فاصلهٔ منظم بین بچه‌های یک Parent.</p></section>
<section><h3>۲. تعریف دقیق</h3><p>Padding فاصله بین content و مرز Element است. Margin فاصله Element با اطرافش است. Gap فاصله بین فرزندان Flex/Grid container را کنترل می‌کند.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>اگر این سه را قاطی کنی، برای فاصله‌سازی Element خالی می‌سازی، یا marginهای تکی روی آیتم‌ها می‌گذاری و Responsive خراب می‌شود.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p>برای نفس کشیدن متن داخل Button از Padding استفاده کن. برای فاصله Button از پاراگراف از Margin استفاده کن. برای فاصله بین آیتم‌های یک row از Gap استفاده کن.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>Empty Flexbox برای فاصله ساختن معمولاً smell است؛ اول Gap یا Padding را بررسی کن.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>داخل جعبه = Padding.</li><li>بیرون جعبه = Margin.</li><li>بین فرزندان یک Parent = Gap.</li></ul></section>
</div>

<section class="comparison-card semantic-complete" id="compare-vw-percent">
<h2>6. 🆚 <span dir="ltr">vw</span> در برابر <span dir="ltr">%</span></h2>
<div class="teacher-flow-grid">
<section><h3>۱. تصویر ذهنی</h3><p><span dir="ltr">%</span> می‌گوید «نسبت به خانهٔ پدرم». <span dir="ltr">vw</span> می‌گوید «نسبت به کل پنجرهٔ شهر».</p></section>
<section><h3>۲. تعریف دقیق</h3><p><span dir="ltr">%</span> معمولاً نسبت به اندازهٔ containing block یا parent محاسبه می‌شود. <span dir="ltr">vw</span> نسبت به viewport width است.</p></section>
<section><h3>۳. چرا این فرق مهم است؟</h3><p>در ForLesson، مقدارهایی مثل <code dir="ltr">33.33vw</code> برای سه پنل کنار هم ممکن است وسوسه‌کننده باشد، اما اگر Parent padding/gap داشته باشد، سه پنل تقریباً عرض کل viewport را می‌گیرند و overflow می‌سازند.</p></section>
<section><h3>۴. مثال واقعی در Elementor 4</h3><p>برای سه ستون داخل یک container، Flex/Grid یا درصد parent-aware بهتر از <code dir="ltr">33.33vw</code> است. برای یک full-bleed hero که باید با viewport حرف بزند، <code dir="ltr">vw</code> قابل دفاع است.</p></section>
<section><h3>۵. اشتباه رایج</h3><p>فرض اینکه <code dir="ltr">vw</code> یعنی درصد parent. این اشتباه باعث scrollbar افقی می‌شود.</p></section>
<section><h3>۶. قوانین طلایی</h3><ul><li>% با والد حرف می‌زند؛ vw با viewport.</li><li>ستون داخل container را با vw نساز مگر دلیل روشن داری.</li><li>هر جا gap/padding داری، vw را با شک نگاه کن.</li></ul></section>
